# Releasing

Pilotfish for OpenCode starts a new experimental version line at `0.0.1`.

## Checklist

1. Update `VERSION`.
2. Add a matching entry at the top of `CHANGELOG.md`.
3. Confirm the installer reads the version from `VERSION`; do not add independent version stamps to prompts.
4. Run `python3 -m unittest discover -s tests -v`, `node --test tests/profile-router.test.mjs`, `node --test tests/integration/config-generation.test.mjs`, and `git diff --check`. The integration test resolves the real OpenCode binary against an isolated fixture and makes no provider request.
5. Run the host-fact gate: `node --test tests/integration/host-fact-config-identity.test.mjs` and `node --test tests/integration/host-facts.test.mjs`. Both resolve the real OpenCode binary against an isolated fixture; the first makes no provider request, the second runs live turns on a free model and needs network access. These are what fail when a pinned OpenCode release moves a host guarantee that G6, G7 and G10 rest on. The second command is bounded: its three tool-observation scenarios are capped at 90 seconds each and its two H7 turns at five minutes each, so the gate cannot run past about fifteen minutes rather than twenty-five, and an unavailable model surfaces within the first four and a half. Triage a failure before acting on it, because that command depends on a free shared model actually emitting a tool call. A failure is **inconclusive** whenever the scenario's precondition was never reached, and the run is then repeated rather than treated as a finding. The suite marks those itself: every such message begins with `INCONCLUSIVE`, so the verdict is read off the output rather than judged. That covers three shapes, not one: nothing observed at all (`the model never called <tool>, so nothing was observed`, with no `tool.execute.before` in the log); the tool called but never as the scenario requires (`the model never called \`task\` with the role the prompt asked for`, or `expected exactly one read of ...`) — the model substituted a valid role or called twice, so a `tool.execute.before` is present while the host claim still went untested; and the call refused before execute (`the call was refused before execute, so H6 was never exercised`), or any record missing from a run killed at its cap (`run killed at its cap, so ...`) — the host never entered execute, so nothing was learned in either direction. A permission refusal is **not a host verdict** and must not block a release: issue #39 traced every observed instance to an uncanonical fixture root that made the host read an in-project path as `external_directory`, so suspect the fixture's path handling before the contract. None of this relaxes an assertion — the refusal guard still fails the run rather than passing an unexercised H6; what is classified is the meaning of the failure, not its threshold. A failure carrying no `INCONCLUSIVE` marker — the call *was* observed, execute ran, and an ordering, key-set, or hook-sequence assertion then failed — is a genuine host change: block the release until the affected row of `docs/profile-router-contract.md` is re-settled, and never relax the assertion instead.
6. Validate JSON syntax for `templates/opencode.base.jsonc`, both preset fragments, and `templates/pilotfish/profiles.json`.
7. Resolve the base plus each preset with the current supported OpenCode release.
8. Inspect all nine public agents with `opencode debug agent <name>`.
9. Confirm the required model IDs and variants still appear in `opencode models --verbose`.
10. Exercise fresh install, repeated install, update with customization, and uninstall restoration.
11. Follow `docs/upstream-sync.md`, review through current `upstream/main`, and update `UPSTREAM_VERSION`.
12. Review `docs/upstream-deviations.md`; every current difference must be represented, and no row may have `Pending` in Source at release.
13. Verify active documentation contains no Claude installation paths or removed files.
14. Run the Node router tests: `node --test tests/profile-router.test.mjs` must prove exact profile data, default-only export, clone count/mappings, same-session rejection, unsupported/cross-preset rejection, post-authorization `session.created` binding, exact marked-child and resumed-task authorization, atomic expiry races, awaited bound-title cleanup on expiry/deletion/disposal, update-failure revocation without unhandled rejection, per-preset profile activation, and routing under an omitted preset.
15. Run the mandatory isolated smoke in an isolated/neutral OpenCode context with `OPENCODE_DISABLE_PROJECT_CONFIG=1`; do not write global configuration. It must prove plugin loading, the exact router plugin tuple and runtime hashes, public primary model/variant unchanged, 24 hidden ChatGPT clones or no AntiGravity clones, and the foreground host sequence `tool.execute.before` → `session.created` → child chat → `tool.execute.after`. Before must add a transient marker and leave authorization unbound; the synchronous created event must bind the exact post-authorization child ID and clean title, and child chat must reject if it races ahead. Only that bound child may start, its title must be clean before provider execution, and after must restore mutable description/result values and clear authorization. OpenCode may retain the digest in raw tool-input history; verify it contains no prompt or credential data. A pre-existing sibling retitled to the marker must reject, two concurrent same-role calls must each accept their own child, and stale authorization must expire after 30 seconds even when Task throws and after is skipped. For a bound child in that failure path, expiry must restore the still-marked title before removing authorization; if a forced host update fails, authorization must still revoke without an unhandled rejection, although manual child-title cleanup may be required. Exercise timer races with child chat and after, and confirm parent deletion and plugin disposal perform equivalent best-effort restoration. A resumed Task must validate and accept only its exact `task_id` without marker mutation or marker restoration. It must also prove unsupported routing fails before assistant/provider execution with no assistant/provider execution. Capture `--print-logs` to verify the exact router reason when OpenCode's standard JSON output reports only `Unexpected server error`. Confirm CLI selection of an internal hidden name does not execute that clone, while allowing for OpenCode's documented fallback to its default primary. The smoke must restart OpenCode, resume a prior Pilotfish session with a different primary model, and prove persisted-history recovery rejects that cross-process resume before assistant/provider execution. Experimental background Task timing is unsupported and must not replace this foreground smoke.
16. Run the mandatory authenticated ChatGPT provider smoke only with the exact approved models. Dispatch one bounded Luna/low task, allow at most five minutes (a five-minute maximum), and use no retries. If credentials or model prerequisites are unavailable, block the release: the release is blocked; do not claim the gate passed.
17. Run the mandatory authenticated AntiGravity provider smoke with its exact approved credentials, models, and variants. If credentials or model prerequisites are unavailable, block the release: the release is blocked; do not claim the gate passed.
18. Confirm smoke and provider gates make no global writes and never mutate global `model` or `default_agent`.
19. Review the release diff, commit, tag, and publish.

```bash
git tag vX.Y.Z
git push
git push --tags
gh release create vX.Y.Z --title "vX.Y.Z" --notes-from-tag
```

## Compatibility Notes

Record the tested OpenCode version in every release entry. If a provider changes a model ID or variant, update the affected preset and treat that as a user-visible compatibility change.

Prompt files under `templates/pilotfish/prompts/`, public agent definitions in `templates/opencode.base.jsonc`, and the required `profile-router.mjs` and `profiles.json` runtime artifacts are the sources of truth. Do not validate releases against a maintainer's installed files without first checking for local customization.
